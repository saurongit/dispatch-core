# Участие в разработке

**Русский** | [English](CONTRIBUTING.md)

Dispatch Core отделяет бизнес-правила от структур данных провайдеров и
UI-фреймворков.
Изменения должны сохранять эту границу.

## Проверка при разработке

```bash
python -m venv .venv
.venv/bin/pip install -e '.[server,dev]'
.venv/bin/ruff check .
.venv/bin/pytest
```

Задайте `TEST_DATABASE_URL`, чтобы запустить интеграционные и конкурентные тесты
PostgreSQL. При доступной тестовой базе `make coverage` контролирует настроенный
минимальный уровень покрытия ветвей.

## Правила изменений

- Добавляйте или обновляйте тесты для каждого доменного перехода и каждой ветви
  ошибки или повторной попытки.
- Размещайте доменные инварианты в агрегатах, а не в обработчиках Telegram/MAX.
- Никогда не выполняйте сетевой I/O провайдера внутри транзакции базы данных.
- Сохраняйте миграции однонаправленными и идемпотентными.
- Во всех запросах сохраняйте изоляцию организаций.
- Никогда не коммитьте реальные токены, закрытые ключи, `.env`, файлы сессий или
  дампы.
- Документируйте видимые пользователю изменения возможностей и совместимости.

Обсуждайте крупные изменения жизненного цикла до написания кода. Для новой
отрасли обычно нужен пакет или адаптер, а не форк и не ещё один параллельный
автомат состояний.
