# Связность и устойчивый исходящий доступ к Telegram

**Русский** | [English](CONNECTIVITY.md)

Ограниченный или нестабильный доступ к Telegram обрабатывается на транспортной
границе. Честное обещание продукта — **настраиваемый альтернативный исходящий
маршрут**, а не «Telegram работает всегда»: ни прокси, ни туннель, ни провайдер
не могут гарантировать доступность при любой сетевой политике, аварии или
проблеме с учётными данными.

## Модель исполнения

```text
Адаптер Telegram
      |
      +--> прямой HTTPS
      |
      +--> настроенный HTTP/SOCKS-прокси (например, локальная точка WireProxy)

Адаптер MAX использует собственную настройку прямого доступа или прокси.
Доменный и прикладной код ничего не знают о маршрутах и данных туннелей.
```

Оба рабочих адаптера сейчас принимают один необязательный URL прокси через
секретную настройку. Репозиторий также содержит детерминированную модель выбора
маршрута с приоритетом и метаданными состояния. Автоматические проверки,
управление процессом WireProxy, подписанная удалённая доставка и переключение
маршрутов в реальном времени пока не подключены к исполняемой системе и остаются будущим
модулем управления связностью.

## Целевая безопасная доставка конфигурации

1. Установка создаёт локальную идентичность; закрытый ключ остаётся локально.
2. Управляющий API возвращает версионированные, ограниченные по времени и
   подписанные метаданные по HTTPS.
3. Локальный модуль проверяет идентичность установки, подпись, хеш, срок
   действия и монотонность версии до принятия данных.
4. Чувствительные параметры маршрута шифруются для конкретной установки или
   загружаются по короткоживущей ссылке; они никогда не помещаются в публичный
   репозиторий.
5. Кандидатный маршрут проходит проверку до включения, а последняя рабочая
   версия остаётся доступной для отката.
6. Логи показывают состояние маршрута, но скрывают токены, адреса и закрытые
   ключи.

Для обновления следует использовать проверенный фреймворк или реализацию, а не
самописную криптографию. Обязательны подписанные метаданные версии, срок
действия и защита от отката или замораживания обновлений.

## Правила переключения

- выбирать исправный маршрут с наименьшим числовым приоритетом;
- при необходимости предпочитать исправный прямой доступ;
- добавлять паузу и случайный разброс интервалов проверки;
- не переносить уже выполняющийся запрос между маршрутами;
- повторять только операции, для которых контролируется эффект дублирования;
- показывать состояние `degraded`, если резервный маршрут работает, и
  `unavailable`, если не работает ни один.

Telegram polling — самый простой вариант без публичного входящего порта, и он
полностью поддерживается. Telegram webhook нельзя использовать одновременно с
polling. MAX также запрещает одновременные polling и webhook; актуальная
документация рекомендует HTTPS webhook для рабочей среды, а polling — для
разработки и тестирования.

Документация провайдеров:

- MAX API: <https://dev.max.ru/docs-api>
- Подписка MAX webhook: <https://dev.max.ru/docs-api/methods/POST/subscriptions>
